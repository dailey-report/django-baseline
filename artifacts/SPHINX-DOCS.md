Generate Documentation with Sphinx
==================================

API documentation built from docstrings (Google style, via napoleon). Sphinx is an ad hoc
install, not a project requirement: it lives in the container user's site-packages and is lost
when the container is recreated, so reinstall as needed.

Paths: `django_root/` on the host is `/opt/app` in the container, so the docs tree is
`django_root/docs/` on the host and `/opt/app/docs` in the container.

```text
django_root/docs/
  source/conf.py      (committed; from artifacts/example-sphinx-conf.py)
  source/index.rst    (committed; hand written)
  source/api/         (generated by apidoc, gitignored)
  build/              (generated html, gitignored)
```

## One Time Setup

On the host, create the docs tree and install the example configuration, then set `project`,
`copyright` and `author` in it:
```bash
mkdir --parents django_root/docs/source
cp artifacts/example-sphinx-conf.py django_root/docs/source/conf.py
```

Create the root page; `api/modules` is the table of contents apidoc generates:
```bash
cat > django_root/docs/source/index.rst <<'EOF'
Project Documentation
=====================

.. toctree::
   :maxdepth: 2

   api/modules
EOF
```

## Install Sphinx

In the running container (`--user` because the container runs as devuser, which cannot write
system site-packages):
```bash
docker compose exec baseline python -m pip install --user sphinx
```

Invoke sphinx as `python -m ...` throughout: `--user` puts its scripts in `~/.local/bin`,
which is not on PATH.

## Build

In a container shell (`docker compose exec baseline bash`):
```bash
cd /opt/app/docs
# regenerate api stubs; excludes are fnmatch patterns, quoted so the shell does not expand them
python -m sphinx.ext.apidoc --force --output-dir source/api .. \
    '../manage.py' '../*/migrations' '../docs'
python -m sphinx --builder html source build/html
```

Rerun both after adding or removing modules; docstring edits only need the second command.
`conf.py` calls `django.setup()`, so the build needs the same environment as the app (run
it in the container, not on the host).

## View

The build lands on the host through the bind mount:
```bash
xdg-open django_root/docs/build/html/index.html
```
